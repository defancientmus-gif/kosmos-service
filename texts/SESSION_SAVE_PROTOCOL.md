# SESSION_SAVE_PROTOCOL — правила памяти между чатами

## Цель

Новый чат, сжатие контекста или завершение сессии не должны ломать непрерывность проекта.

Проект живёт не в одном чате, а в репозитории:

- постоянная философия и решения — в `texts/README.md`;
- текущая задача и ближайшие шаги — в `texts/NEXT.md`;
- повторяемые промты — в `texts/PROMPTS.md`;
- тематические стратегии — в отдельных документах `texts/`;
- реальные документы, ключи и заполненные таблицы — только локально в ignored-папках.

## Начало новой сессии

Каждый новый агент сначала делает:

1. прочитать `CLAUDE.md`;
2. прочитать `texts/README.md`;
3. прочитать `texts/NEXT.md`;
4. выполнить `git status --short --branch`;
5. смотреть только файлы, связанные с текущей задачей.

Если пользователь создал новый чат, первым сообщением лучше дать bootstrap-промт из `texts/PROMPTS.md`.

## Конец сессии

Перед финальным ответом, если были решения, правки или новые факты, агент обязан обновить `texts/NEXT.md`.

В `NEXT.md` сохранять:

- что сделано;
- что осталось следующим шагом;
- какие решения приняты;
- какие файлы изменены или оставлены грязными;
- какие блокеры есть;
- что нельзя трогать без явной команды владельца.

## Куда сохранять разные типы памяти

### Философия и принципы

Сохранять в `texts/README.md`, если это устойчивое правило проекта.

Примеры:

- минимум шума;
- цифровой клон сервиса;
- не обещать финальную цену ремонта до диагностики;
- спорные юридические вопросы отдавать бухгалтеру.

### Текущие todo

Сохранять в `texts/NEXT.md`.

Не оставлять важные задачи только в чате.

### Промты

Сохранять в `texts/PROMPTS.md`.

Туда складывать:

- bootstrap-промт нового чата;
- промт для аккуратного senior-инженерного режима;
- промты для бизнес-анализа;
- промты для разбора документов;
- промты для будущих агентов.

### Архитектурные решения

Сохранять в тематический документ:

- сайт — `texts/SITE_STRATEGY.md`;
- CRM/ИИ-агент — `texts/CRM_AGENT_STRATEGY.md`;
- документы/финансы — `texts/DOCUMENTS_FINANCE_HUB.md`;
- цифровой сейф — `texts/DIGITAL_VAULT_STRUCTURE.md`;
- ФНС — `texts/FNS_EXPORT_CHECKLIST.md`.

### Юридические и бухгалтерские вопросы

Сохранять в:

- `texts/DOCUMENTS_FINANCE_HUB.md` — как системное правило;
- `data/live/accountant_questions.csv` — как рабочий реестр, если есть реальные данные.

Спорные юридические решения не принимать на глаз. Агент готовит вопрос и контекст, финальную проверку делает бухгалтер.

## Что не сохранять в git

Нельзя коммитить:

- пароли;
- PIN КЭП;
- токены;
- `.env`;
- реальные документы ФНС, банка, поставщиков;
- подписи и сертификаты;
- заполненные финансовые таблицы;
- персональные данные клиентов.

Для этого используются ignored-папки:

- `_inbox/`;
- `_archive/`;
- `data/live/`;
- `private/`;
- `secrets/`.

## Перед коммитом

Всегда проверить:

1. `git status --short --branch`;
2. `git diff --check`;
3. `git diff --cached --name-only`, если есть staged-файлы.

Коммитить только нужные файлы. Не использовать `git add -A` вслепую.

Если `projects/site/index.html` грязный, не трогать и не коммитить его, пока владелец явно не вернётся к сайту.

## После автоматического сжатия контекста

Если агент видит, что контекст был сжат, он не начинает заново.

Он:

1. читает summary / доступный контекст;
2. читает `texts/README.md`;
3. читает `texts/NEXT.md`;
4. проверяет `git status`;
5. продолжает с ближайшего безопасного шага.

## Короткая формула

Чат может исчезнуть. Репозиторий должен помнить.
