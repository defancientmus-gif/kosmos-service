# Космос Сервис — карта памяти

Рабочий репозиторий для проектов сервиса по ремонту телефонов Космос Сервис.

## Контекст бизнеса

- Работаем с физлицами и корпоративными клиентами.
- Главный принцип: быстрый ответ, прозрачный ремонт, без сюрпризов.
- Тон коммуникации: живой, конкретный, без канцелярита.
- Главная цель: оптимизировать и улучшить среду формирования клиентской базы и прибыли сервиса.
- Сайт и цифровые инструменты — фундамент, ниже которого сервис не спускается даже в плохие времена.
- Развиваем цифровой клон сервиса: ремонт, новая и б/у техника, ПО, корпоративные задачи, современные каналы связи.
- Главная внутренняя цель — личный операционный ИИ-агент владельца: документы, платежи, заявки, CRM, бухгалтерия, закупки, SMM, сайт и вся рутина сервиса в одном управляемом контуре.
- Глобальная миссия всех проектов: минимум шума. Человек должен интуитивно понимать, куда нажимать, а лучше вообще не нажимать — чтобы система сама доводила до следующего шага.

## Структура

- `texts/README.md` — карта памяти и постоянный контекст.
- `texts/NEXT.md` — текущая задача, итоги прошлой сессии и следующий шаг.
- `texts/BUSINESS_PROFILE.md` — реквизиты ИП, публичные источники и текущие сервисы.
- `texts/AGENT_VISION.md` — философия личного операционного агента и долгосрочная цель цифрового штаба сервиса.
- `texts/OWNER_IP_VAULT.md` — правила локального сейфа владельца и ИП без коммита персональных данных.
- `texts/SITE_STRATEGY.md` — философия и стратегия сайта.
- `texts/CRM_AGENT_STRATEGY.md` — стратегия персонального ИИ-агента и CRM.
- `texts/DOCUMENTS_FINANCE_HUB.md` — склад документов, платежей, расходов, напоминаний и вопросов бухгалтеру.
- `texts/FNS_EXPORT_CHECKLIST.md` — чеклист выгрузки документов из ЛК ФНС для цифрового сейфа.
- `texts/DIGITAL_VAULT_STRUCTURE.md` — структура цифрового сейфа, входящих папок, архива и реестров.
- `texts/SESSION_SAVE_PROTOCOL.md` — правила сохранения памяти между чатами и после сжатия контекста.
- `texts/PROMPTS.md` — повторяемые промты для новых чатов, handoff, разбора документов и будущих агентов.
- `data/templates/` — шаблоны таблиц для документов, платежей, расходов, поставщиков и действий агента.
- `projects/site/` — личный сайт сервиса.
- `projects/tg-bot/` — бот для приёма заявок.
- `projects/crm/` — CRM или внутренняя админка, если понадобится.
- `projects/ops-agent/` — будущий локальный агент выгрузки документов и рутины.

## Решения

- API ключи храним только в `.env`.
- Перед деплоем проверяем локально.
- Коммитим только нужные файлы.
- Ошибки логируем, клиенту не показываем стектрейсы.
- Спорные юридические вопросы обсуждаем с живым бухгалтером.
- Сайт не обещает финальную цену ремонта до диагностики.
- Предзаказ техники сначала оформляем как заявку на подбор, пока не проверены поставщик, документы и налоговые нюансы.
- Для сайта используем реальные материалы сервиса: фото/видео мастерской, актуальные бренд-файлы и фирменный цвет морской волны.
- Визуальный логотип и wordmark — `KOSMOS`; рабочее название проекта — `Космос Сервис`.
- Текущая CRM: LiveSklad.
- Реальные документы, ключи, подписи и заполненные финансовые таблицы храним локально в игнорируемых папках, не в git.
- Паспортные данные, регистрационные документы, банк, ФНС и документы бизнеса могут храниться только в локальном цифровом сейфе на MacBook; публичный сайт и GitHub к ним не привязывать.
- `Документы Космос/11_Владелец_ИП/` — локальный источник правды по владельцу и ИП; в git допускаются только пустые шаблоны и инструкции.
- Бухгалтер остаётся в контуре налоговых решений; агент собирает факты, готовит вопросы и черновики, но не принимает налоговые решения сам.
- Чат может оборваться или сжаться; устойчивую память храним в репозитории: философию в `README`, текущие задачи в `NEXT`, промты в `PROMPTS`.
